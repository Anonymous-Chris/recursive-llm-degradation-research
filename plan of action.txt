Recursive biomedical QA study — action plan

Current repository state
- The generation pipeline is in src/biomed_recursive/ (prepare_data and
  run_chain); matrix and run verification helpers are in scripts/.
- configs/experiment.yaml currently specifies Qwen2.5-3B, seeds 42 and 123,
  generations G0-G3, a 5,000-example initial pool, and 1,000 held-out labels.
- Colab combined-evaluation notebooks and saved analysis outputs are under
  notebooks/evaluation_qwen2.5-0.5b/ and notebooks/evaluation_qwen2.5-3b/.
- Standalone evaluate.py, statistics.py, and metrics.py modules are not present
  in the current checkout. Evaluation currently uses the notebooks.

Next steps

1. Confirm the experiment definition
   - Confirm model, seeds, data sizes, conditions, and decoding settings in
     configs/experiment.yaml before launching new runs.
   - Keep results from different configurations separate and record the config
     alongside each run.

2. Prepare data and run models
   - Install requirements and authenticate with Hugging Face as needed.
   - Prepare the fixed train and held-out evaluation data.
   - Run the configured condition/seed matrix with scripts/run_matrix.py, or
     run an individual condition using biomed_recursive.run_chain.
   - Verify run files and data provenance with scripts/verify_run.py.
   - Preserve run metadata, generated answers, and predictions for analysis.

3. Evaluate saved runs
   - Upload the appropriate run CSV files to the matching Colab evaluation
     notebook under notebooks/evaluation_qwen2.5-0.5b/ or
     notebooks/evaluation_qwen2.5-3b/.
   - Run the notebook from top to bottom and retain its tables and plots.
   - Run the cross-condition, cross-seed notebook after the required seed and
     condition results are available.
   - Check that analyzed files use the same gold examples and compatible
     model/generation settings.

4. Review and report
   - Summarize changes across generations and conditions using the saved
     metrics, uncertainty estimates, and plots.
   - Treat entity overlap, perplexity, and text similarity as descriptive
     measures; do not present them as clinical safety or factuality judgments.
   - State the evaluated model, data, seeds, and generation settings, and note
     that external clinical adjudication is outside this repository's current
     analysis workflow.

5. Maintain the repository
   - Keep README.md and this plan aligned with the commands and files that
     actually exist.
   - Before removing files during cleanup, search for references in notebooks,
     scripts, and documentation and confirm the files are not needed by an
     active workflow.
